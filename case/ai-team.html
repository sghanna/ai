Running a Team of AI Tools I make the final call.

I use three AI tools from three companies: Claude Code, Codex, and Antigravity. Early on I used whichever one was open. Then my Claude usage ran out halfway through a day of work, and I started treating the three of them like a small team with different strengths, a shared budget, and rules for checking each other.

01Problem

One tool doing everything

By mid-afternoon I had hit my Claude session limit. Meanwhile Codex had almost its whole week of usage left, and Antigravity was sitting idle. The work was fine. The budget was not.

02Action

The split

I stopped asking which AI is best and started asking which AI is best for this job, at what cost.

Builds and fixes

Codex

It does the long, heavy work: code, browser tasks, first reviews.

"When you hand things off to Codex, don't NERF Codex. Let it use all tools and abilities at its disposal."

  • Code
  • Browser tasks
  • First reviews
Checks and writes

Claude

It reviews Codex's work, makes judgment calls, and writes anything a person will read. It works in short, focused passes, because its budget is the one that runs out.

  • Reviewing Codex's work
  • Judgment calls
  • Anything a person will read
Researches and drafts

Antigravity

It does web research, first-pass bug hunting, and simple pages. Codex verifies its research before anyone relies on it.

  • Web research
  • First-pass bug hunting
  • Simple pages
Decides

Me

The tools propose, check, and argue. I decide what ships.

  • What ships

Every handoff is a file. Everything is handed off as a written brief in a file, never a pasted prompt, so each step can be checked later. Codex also pauses itself when its weekly usage reaches 95%, instead of failing halfway through a job.

03A scored test

Testing a tool before trusting it

"it isn't perfect, but it did find unique bugs."

That was my doubt about Antigravity. So Codex scored Antigravity's code reviews against the same brief the other two tools had, with a five-part rubric.

  • Accuracy 30%
  • Evidence 20%
  • Coverage 20%
  • Usefulness of the proposed action 20%
  • Confidence matched to evidence 10%

Each model got two tries: a first report, then a revision after feedback. The scores describe these reports, not the models in general. They still settled the question: Flash is worth keeping as an extra bug hunter, and its findings always get a second check.

04A joint decision

Two reviewers, one decision

I wanted to borrow from two popular open-source job-search tools. I asked Claude and Codex to "fully review the code and decide together."

My rule for giving back: fix what we use, look for security holes that a compromised AI could exploit, send no more than three pull requests to any one project a week, and check again right before sending that nobody else has already fixed it.

05Result

What I learned

1 day

From "use whatever is open" to a written split of the work, a budget rule, and a weekly review.

  • A written split of the work
  • A budget rule
  • A weekly review
  • Budget is a design constraint. Once I could see where the usage went, the split of work followed.
  • Measure a tool before trusting it. A rubric turned "I'm doubtful" into a score and a clear role.
  • Two reviewers beat one only if each has to answer the other with evidence.
  • Every handoff is a file. That makes the work checkable, and it makes this write-up possible.
  • I make the final call. The tools propose, check, and argue; I decide what ships.
