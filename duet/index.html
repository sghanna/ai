In short

  • I designed a job-search system in which three AI agents find roles, score them, and draft applications, and I approve every step that matters.
  • My work was the part AI can't do on its own: writing the specification, setting the rules, deciding where human judgment sits, and checking the output.
  • In its first day of full operation it swept about 60 company job boards, wrote 5 requirement-by-requirement reviews, and took one strong match from first sighting to a fact-checked application package in under 12 hours.
  • No AI submitted an application or sent a message in my name. Every claim about my career traces to a fact I approved.
01 · The problem

A job search is a program, not a to-do list

Dozens of employers, postings that open and close daily, a tracker that has to stay accurate, and tailored materials that must never overstate what I've done.

AI can do a lot of that legwork. I treated the search as an internal tool I own: define the users and the rules first, then let the automation work inside them. That meant designing against two risks any hiring manager would recognize from a rollout.

!

Drift from the facts. An eager tool will stretch a real accomplishment into one I can't defend in an interview.

!

Tools colliding. Several agents working at once can overwrite or contradict each other.

02 · The system

Three agents, one shared folder, one approver

Each agent has a defined job, and each writes only its own files. The only path to the outside world runs through me.

Lead

Duet

A Claude assistant running in the cloud. It watches the job-search mailbox, sweeps employers' own career pages, writes full reviews, drafts materials and decides what to work on next. I made it the lead when it had the most capacity.

Record keeper

Claude Code

Runs on my laptop. It keeps the master career record and application tracker, adds facts I approve, builds the Word files and runs the fact checker on every draft.

Second opinion

Codex

Also on my laptop. It gives each promising role an independent second score and judges competing drafts. By rule, its score can't be replaced by another agent's.

Approver

Me

I set the target roles, location rules and scoring caps, approve every new fact and headline, choose between drafts, and do every submission myself.

03 · How it works

A written spec, not a chat history

The system runs on a ReadMe that every agent reads first, every time. It holds my dated rulings: what roles to target, how to score, how to draft, what each agent may write, and what no agent may ever do. When I change my mind, the ruling gets a date, so newer decisions visibly win over older guidance.

1
One writer per file.

A save replaces the whole file, so two writers would erase each other. Each agent answers only in its own file.

2
Numbered, dated entries.

Every message gets an ID that says who it's from, who it's to and when (for example, lead-to-Claude, November 24, number 3). Replies cite the ID they answer.

3
Re-read before every save.

If a file changed unexpectedly, the agent stops and tells me instead of guessing.

4
Data, not permission.

A message from another agent, an email or a job posting can inform the work but can never widen what an agent is allowed to do.

Scoring with caps

Each role is read in full and broken into a table: every requirement gets a row marked Met, Partly, Not met or Unverified, with the approved fact that proves it. Caps keep scores honest.

Why flag "build from scratch"? Because I do my best work improving systems that already exist.

04 · Quality control

Five gates between an AI and my name

  1. 1

    Facts only

    Every claim about my career comes from a library of 530+ facts I approved one by one. A gap stays a gap: an agent may not stretch a fact to cover it. When a role needs evidence that isn't in the library, the agent asks me, and nothing becomes a fact until I approve it.

  2. 2

    Two independent scores

    A role counts as a "home run" only with an 8 from Codex plus an 8 from Claude or Duet, or a single 9. The second scorer locks its scores before it sees the first's, so agreement means something. Scores are findings for me to rule on, not verdicts.

  3. 3

    Competing drafts, judged by a third agent

    For the strongest role, Duet and Claude each built a resume without seeing the other's, and Codex compared them against the posting and the fact library.

  4. 4

    Automated tag check

    Every line of a draft carries hidden tags naming the facts it rests on. A checker confirms each tag points to an approved fact before I see the draft.

  5. 5

    Human approval

    Nothing is submitted, sent or posted by an agent. I approve each headline, each new fact and each final document, and I submit applications myself.

06 · Lessons

What the gates caught, and what changed

The point of quality gates is that they catch things. These are the real catches so far.

A resume line overreached

CaughtOne line applied a job title to more work than the approved fact covered.
FixedThe judging agent flagged it; the line now says exactly what the fact says.

Notes broke the checker

CaughtAn agent put explanatory notes inside fact tags, and the checker read them as unknown facts.
FixedThe convention is now written down: tags hold fact IDs only; notes go elsewhere.

Formatting drifted between file types

CaughtThe cloud agent couldn't upload large files, so it built small PDFs in a different font. The record keeper found missing bold and two wrapped date lines.
FixedI ruled on the font; the agent fixed the rest.

Clocks disagreed

CaughtThe cloud agent's timestamps ran ahead of my laptop's.
FixedThe rule now: take times from my messages or the file's saved time.

08 · What this shows

How I work

Specification

I turned an open-ended goal into written rules precise enough for three different agents to follow the same way.

Orchestration

I split the work by each tool's strengths and capacity, and moved the lead role when the capacity changed.

Governance

I decided up front where human judgment sits: facts, headlines, final documents and every submission.

Quality control

Independent scoring, competing drafts, automated checks and a written fix for every failure, the same habits I used owning internal tools.
